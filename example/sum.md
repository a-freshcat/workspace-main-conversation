## 五、已知风险

### 1. 运行时文件不要手改

`cordis.yml` / `workspace.json` 会被应用**周期性重写**；手改会在几分钟后消失。

**真实事故**：用 PowerShell `Set-Content -Encoding UTF8` 写 `workspace.json`
⇒ 写入 BOM ⇒ 应用 `JSON.parse` 失败 ⇒ **打不开文件夹**。

**教训**：
- 写 JSON 用 Node `writeFileSync(p, s, 'utf8')`，**不要**用 PowerShell 的 `Set-Content -Encoding UTF8`
- 验证要**和消费者一致**：`JSON.parse(readFileSync(p,'utf8'))` + 显式查前三字节 ≠ `EF BB BF`
  （PowerShell 的 `ConvertFrom-Json` **容忍 BOM**，会假通过）

### 2. 装插件会冲掉补丁

`pnpm add` 会重解析整个 profile、按 bundles 重写 `cordis.yml`，实测冲掉过别人的补丁。

### 3. mtime 很新 ≠ 有人在改

应用运行时自己会重写配置。**判断"谁改的"要读会话记录里的 `tool/call`**，不能只看时间戳。
